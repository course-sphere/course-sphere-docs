# Course Creation API Flow

Quá trình tạo khóa học trên hệ thống được chia làm 5 giai đoạn (Phases) nối tiếp nhau (`/course/create/*`). Dữ liệu mang tính chất quan hệ cha - con chặt chẽ.

## 1. Data Hierarchy & Draft Lifecycle

Hệ thống hoạt động theo cơ chế **"Tạo nháp 1 lần - Đắp dữ liệu liên tục"**.

1. **Phase 1 (Course Metadata):** Khởi tạo khung xương. Gửi payload lần đầu sẽ tạo ra khóa học với `status: "draft"`. BE trả về `course_id`.
2. **Phase 2 (Module):** Dùng `course_id` của bản draft trên để thêm các Module. BE trả về `module_id`.
3. **Phase 3 (Lesson):** Dùng `module_id` để thêm các Lesson vào Module. BE trả về `lesson_id`.
4. **Phase 4 (Material):** Dùng `lesson_id` để đính kèm nội dung học (Video, Quiz, Reading...). BE trả về `material_id`.
5. **Phase 5 (Preview & Submit):** Nút chốt hạ. Hành động "Submit" ở bước này bản chất chỉ là một lệnh `PATCH` để đổi `status` từ `draft` sang `pending` (chờ Admin duyệt).

*Lưu ý:* Nếu Teacher không ưng ý ở bước Preview (Phase 5), họ hoàn toàn có thể quay lại (Back) các Phase trước để gọi API `PATCH` / `PUT` chỉnh sửa bản draft này.

## 2. Frontend Navigation & Action Flow

Frontend (FE) hoạt động dưới dạng một Form Wizard có các bước nối tiếp nhau. Backend (BE) cần nắm rõ logic gọi API ở các nút điều hướng của FE:

- **Nút "Save & Continue" (Next):**
  - FE sẽ gom data ở màn hình hiện tại và gọi API `POST` (nếu tạo mới) hoặc `PATCH` (nếu cập nhật).
  - **Bắt buộc:** BE **phải trả về `id`** của entity vừa được tạo/cập nhật. 
  - Khi nhận được `id` (200/201), FE mới lưu ID này vào state và tự động chuyển user sang trang tiếp theo.

- **Nút "Back" (Previous):**
  - FE thực hiện chuyển trang lùi lại.
  - Khi render lại trang cũ, FE sẽ tự động gọi API `GET /{id}` để lấy lại data cũ từ BE và fill vào form cho user tiếp tục chỉnh sửa.

- **Trạng thái "Draft":**
  - Khóa học sẽ nằm im ở trạng thái `draft` trong suốt quá trình thao tác từ Phase 1 đến Phase 4, cho đến khi user bấm "Submit for Review" ở Phase 5.
