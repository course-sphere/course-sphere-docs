# Course Creation API Flow

Quá trình tạo khóa học trên hệ thống được chia làm 4 giai đoạn (Phases) nối tiếp nhau. Dữ liệu mang tính chất quan hệ cha - con.

## 1. Data Hierarchy (Cấu trúc phân cấp)

Để một khóa học hoàn chỉnh, dữ liệu phải được tạo theo đúng thứ tự sau:
1. **Course (Metadata)** -> Trả về `course_id`
2. **Module** (Cần `course_id`) -> Trả về `module_id`
3. **Lesson** (Cần `module_id`) -> Trả về `lesson_id`
4. **Material** (Cần `lesson_id`) -> Trả về `material_id` (Dữ liệu đa hình)

## 2. Frontend Navigation & Action Flow

Frontend (FE) hoạt động dưới dạng một Form Wizard có các bước nối tiếp nhau. Backend (BE) cần nắm rõ logic gọi API ở các nút điều hướng của FE:

- **Nút "Save & Continue" (Next):** - FE sẽ gom data ở màn hình hiện tại và gọi API `POST` (nếu tạo mới) hoặc `PATCH` (nếu cập nhật).
  - **Bắt buộc:** BE **phải trả về `id`** của entity vừa được tạo. 
  - Khi nhận được `id` (200/201), FE mới lưu ID này vào state và tự động chuyển user sang trang tiếp theo.

- **Nút "Back" (Previous):**
  - FE chỉ thực hiện chuyển trang lùi lại (Route Back).
  - Khi render lại trang cũ, FE sẽ gọi API `GET /{id}` để lấy lại data cũ và điền vào form cho user xem/sửa.

- **Trạng thái "Draft":**
  - Ngay từ Phase 1, khi bấm Continue, khóa học đã được lưu vào DB dưới trạng thái `status: "draft"`. 
  - Nó sẽ ở trạng thái Draft cho đến khi user bấm "Submit for Review" ở bước cuối cùng.
